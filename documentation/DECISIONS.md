# python-sdk — Decisions Log

> **Platform decisions**: [Service Catalog](../../documentation/target-state/service-catalog.md)

| # | Decision | Rationale | Date | Platform Impact |
|---|----------|-----------|------|-----------------|
| 1 | HMAC-SHA256 signature auth | No bearer tokens for merchant API; symmetric key signing | 2026 | No — SDK-scoped |
| 2 | Async-first (httpx) | Modern Python best practice | 2026 | No — SDK-scoped |
| 3 | Documentation is written for the merchant and is the source of truth; it is never shaped by tests or tooling | A README/example must read as a merchant would write it (real values, no test-only placeholders, env vars or markers). Checks follow the docs, not the other way round | 2026-10-08 | No — SDK-scoped |
| 4 | Code blocks in the docs are verified by a separate static checker (`scripts/check_docs.py`), not by the test suite | Every python block is pinned by hash in `scripts/docs_manifest.json`; editing the docs makes the check fail, a developer reviews the change and accepts it with `python scripts/check_docs.py --update` (`make docs-update` is a shortcut). The check never executes the docs: it verifies syntax, `polako.sdk` imports and that calls (to classes, functions and client methods) fit the real signatures. The files in `examples/` are pinned and checked the same way. Blocks with `...` arguments are treated as elided | 2026-10-08 | No — SDK-scoped |
| 5 | `create_order` defaults the language to Serbian (`sr`) through an explicit `DEFAULT_LANGUAGE` constant | The previous default was `next(iter(LANGUAGES))` over a set, so it could be `sr`, `en` or `ru` between interpreter runs. The currency default (`RSD`) is still taken from the one-element set | 2026-10-08 | Merchants that omit `language` now always get `sr` |
| 6 | Unit tests run the SDK against an in-process fake gateway (`httpx.MockTransport`) | Fast and deterministic; the `gateway` fixture patches the `httpx.AsyncClient` the SDK creates, so no production code needs a test hook. End-to-end tests are a separate layer (#14) | 2026-10-08 | No — SDK-scoped |
| 7 | The tests are a separate Poetry project (`tests/pyproject.toml`, own lock file) that installs the SDK from the repository root; the SDK's `pyproject.toml` lists no test dependencies | Building and publishing the SDK is independent of the tests and of whatever their infrastructure needs (test servers, plugins), while the tests stay in the repository for anyone who wants to read them | 2026-10-08 | No — SDK-scoped |
| 8 | The transport retries only requests that carry an `Idempotency-Key` | Only then can a repeat not do the work twice. Such a request is retried on HTTP 429, 500, 502, 503 and 504 and on network errors that a repeat can cure (timeouts, connection and protocol failures; not 501, 505, an unsupported address or too many redirects) (3 attempts, exponential back-off, `Retry-After` honoured when it is short, the same key and body on every attempt); other 4xx are never retried. Payment methods carry no key and are sent once; changing that is a separate decision | 2026-10-08 | Subscription creation is retried safely; payment methods are unchanged |
| 9 | A webhook is verified before it is read | The signature is checked over the raw body exactly as received (HMAC-SHA256, `hmac.compare_digest`), and only then is the body decoded (a UTF-8 JSON object). A forged body is always a signature error, never a payload error; a body that was parsed and serialized again does not match. An unknown event name is returned as `UnknownSubscriptionEvent` instead of raising, so a new kind of event does not break a merchant's endpoint | 2026-10-08 | No — SDK-scoped |
| 10 | The registration-failure notification is a model of its own, not a lifecycle event | It has no `event` field and `success` is always 0, so the model says `event = None` and `success = 0`, and the parser accepts only that. Each parser rejects the other kind and points to the right function, so one URL used for both cannot turn a charge into a failure. Its `order_id` always equals `subscription_id` and is not kept. A signature that is present is always checked; a missing one is rejected unless `allow_unsigned=True` is passed, which marks the result `signature_verified=False` (a subscription without a platform is notified unsigned) | 2026-10-08 | No — SDK-scoped |
| 11 | The subscription surface is specified before it is built | `documentation/SUBSCRIPTIONS-SPEC.md` holds the gateway contract, the merchant example and the interface; tests, code and docs follow it, and a change is made in the spec first, with a change-log row | 2026-10-08 | No — SDK-scoped |
| 12 | Tests use generated data: `tests/generators.py` and `tests/factories.py`, no fixed literals | Two runs never share values, and a literal appears only where it is what the test checks. A test overrides only the fields it is about | 2026-10-08 | No — SDK-scoped |
| 13 | Python 3.10 to 3.13 are supported and tested in CI on every version | `requires-python` is `>=3.10`; code and tests avoid what was added later (for example `datetime.UTC`, `tomllib`, `fromisoformat` reading a trailing `Z`) | 2026-10-08 | No — SDK-scoped |
| 14 | End-to-end tests run the SDK against a local emulator of the gateway over real HTTP, with a merchant endpoint written as the documentation tells a merchant to write it | The fake gateway cannot show that the raw bytes the gateway signed are the bytes the merchant's framework hands to the SDK, that retries use the same key and body on the wire, or how a whole subscription goes from creation to cancellation. The emulator (aiohttp, a dependency of the tests project only) models the documented contract on free loopback ports; the fake-gateway tests stay for failures that are hard to produce over a socket. A model cannot show where the real gateway differs, so a check on the staging environment remains a separate step | 2026-10-08 | No — SDK-scoped |
| 15 | The registration form is rendered by the SDK into a complete page, with the names the card processor expects and strict rules for the address | A merchant without our JavaScript SDK should not assemble a 3DS form by hand: the helper posts the nine processor fields of a `form_post` (not the gateway's camelCase names), passes an `hpp_form_post` through unchanged, and redirects for the `iframe` wire type instead of framing it. Because the address and the values come from a remote system, it must be an http or https URL with no whitespace or control characters, every value is escaped, the one script is constant, and `auto_submit=False` serves sites that forbid inline scripts | 2026-10-08 | No — SDK-scoped |
| 16 | Subscriptions are read and managed with the platform API key, through methods that are never retried, and their code is split by what it does | A merchant's code should list, read, pause, resume and cancel subscriptions with the key it already signs payments with. The server has no `Idempotency-Key` on pause, resume and cancel, and a repeat after a lost answer would meet the changed status and be refused with 409, which cannot be told from a real refusal, so none of the management methods is repeated and the docs tell the merchant to read the subscription before repeating a change. An unknown value of a status or an interval from the server stays the raw text, so that a value added later does not break a merchant's listing; a missing or malformed required field is an `HttpRequestError` whose cause is the reason. The code follows the layout of the server's models, by operation (`_subscription_list.py`, `_subscription_detail.py`), with the reading of server values in `_decoding.py` and the checks of the caller's arguments in `_validation.py`, which only checks. The status of the work is in the specification | 2026-10-09 | No — SDK-scoped |

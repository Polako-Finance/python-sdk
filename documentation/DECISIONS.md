# python-sdk — Decisions Log

> **Platform decisions**: [Service Catalog](../../documentation/target-state/service-catalog.md)

| # | Decision | Rationale | Date | Platform Impact |
|---|----------|-----------|------|-----------------|
| 1 | HMAC-SHA256 signature auth | No bearer tokens for merchant API; symmetric key signing | 2026 | No — SDK-scoped |
| 2 | Async-first (httpx) | Modern Python best practice | 2026 | No — SDK-scoped |
| 3 | Documentation is written for the merchant and is the source of truth; it is never shaped by tests or tooling | A README/example must read as a merchant would write it (real values, no test-only placeholders, env vars or markers). Checks follow the docs, not the other way round | 2026-10-08 | No — SDK-scoped |
| 4 | Code blocks in the docs are verified by a separate static checker (`scripts/check_docs.py`), not by the test suite | Every python block is pinned by hash in `scripts/docs_manifest.json`; editing the docs makes the check fail, a developer reviews the change and accepts it with `python scripts/check_docs.py --update` (`make docs-update` is a shortcut). The check never executes the docs: it verifies syntax, `polako.sdk` imports and that calls fit the real signatures. Blocks with `...` arguments are treated as elided | 2026-10-08 | No — SDK-scoped |
| 5 | `create_order` defaults the language to Serbian (`sr`) through an explicit `DEFAULT_LANGUAGE` constant | The previous default was `next(iter(LANGUAGES))` over a set, so it could be `sr`, `en` or `ru` between interpreter runs. The currency default (`RSD`) is still taken from the one-element set | 2026-10-08 | Merchants that omit `language` now always get `sr` |
| 6 | Tests run the SDK against an in-process fake gateway (`httpx.MockTransport`), never against the network | Fast and deterministic; the `gateway` fixture patches the `httpx.AsyncClient` the SDK creates, so no production code needs a test hook | 2026-10-08 | No — SDK-scoped |
| 7 | The tests are a separate Poetry project (`tests/pyproject.toml`, own lock file) that installs the SDK from the repository root; the SDK's `pyproject.toml` lists no test dependencies | Building and publishing the SDK is independent of the tests and of whatever their infrastructure needs (test servers, plugins), while the tests stay in the repository for anyone who wants to read them | 2026-10-08 | No — SDK-scoped |
| 8 | The transport retries only requests that carry an `Idempotency-Key` | Only then can a repeat not do the work twice. Such a request is retried on HTTP 429, 5xx and network errors (3 attempts, exponential back-off, `Retry-After` honoured when it is short, the same key and body on every attempt); other 4xx are never retried. Payment methods carry no key and are sent once; changing that is a separate decision | 2026-10-08 | Subscription creation is retried safely; payment methods are unchanged |
| 9 | A webhook is verified before it is read | The signature is checked over the raw body exactly as received (HMAC-SHA256, `hmac.compare_digest`), and only then is the body decoded (a UTF-8 JSON object). A forged body is always a signature error, never a payload error; a body that was parsed and serialized again does not match. An unknown event name is returned as `UnknownSubscriptionEvent` instead of raising, so a new kind of event does not break a merchant's endpoint | 2026-10-08 | No — SDK-scoped |
| 10 | The registration-failure notification is a model of its own, not a lifecycle event | It has no `event` field and `success` is always 0, so the model says `event = None` and `success = 0`, and the parser accepts only that. Each parser rejects the other kind and points to the right function, so one URL used for both cannot turn a charge into a failure. Its `order_id` always equals `subscription_id` and is not kept. A signature that is present is always checked; a missing one is rejected unless `allow_unsigned=True` is passed, which marks the result `signature_verified=False` (a subscription without a platform is notified unsigned) | 2026-10-08 | No — SDK-scoped |
| 11 | The subscription surface is specified before it is built | `documentation/SUBSCRIPTIONS-SPEC.md` holds the gateway contract, the merchant example and the interface; tests, code and docs follow it, and a change is made in the spec first, with a change-log row | 2026-10-08 | No — SDK-scoped |
| 12 | Tests use generated data: `tests/generators.py` and `tests/factories.py`, no fixed literals | Two runs never share values, and a literal appears only where it is what the test checks. A test overrides only the fields it is about | 2026-10-08 | No — SDK-scoped |
| 13 | Python 3.10 to 3.13 are supported and tested in CI on every version | `requires-python` is `>=3.10`; code and tests avoid what was added later (for example `datetime.UTC`, `tomllib`, `fromisoformat` reading a trailing `Z`) | 2026-10-08 | No — SDK-scoped |
